# Playbooks

Step-by-step procedures for running Factory loops.

---

## Purpose

Playbooks translate concepts and doctrine into actionable sequences. Where concepts explain *what* and doctrine explains *why*, playbooks explain *how*.

A playbook should be detailed enough that someone unfamiliar with the process can follow it step by step.

---

## What Makes a Good Playbook

- **Sequential steps** — Clear order of operations
- **Entry/exit criteria** — When to start, when to stop
- **Checkpoints** — Verification points to ensure quality
- **Examples** — Optional illustrations or edge cases
- **Honesty** — Marks sections as "planned" or "in development" when not yet written

## Contributing Playbooks

Good playbooks come from:
- Repeated practice of a workflow
- Documentation of the steps that worked
- Honest acknowledgment of failure modes

If a workflow isn't documented yet, mark it as planned rather than inventing procedures.

---

*Playbooks should be tested in practice before being documented.*
