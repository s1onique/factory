# What is Factory?

Factory is an open process for building and improving feedback loops around software work.

It helps teams turn repeated engineering practice into inspectable doctrine, reusable templates, review frameworks, examples, talks, and onboarding paths. The goal is not to prescribe one true way to build software, but to make useful development loops visible enough that others can run them, challenge them, and improve them.

---

## What Factory Is

- **A feedback loop framework.** Factory provides structure for framing problems, slicing work into actionable increments (ACTs), making small changes, verifying results, and capturing learning.

- **A knowledge extraction process.** Repeated practice becomes doctrine; patterns become templates; lessons become playbooks.

- **A public process.** The goal is reuse and iteration by others, not internal lock-in.

---

## What Factory Is Not

- **Not a methodology gospel.** Factory does not claim to be the one true way. It adapts to context.

- **Not architecture review.** While it includes evaluation tools, Factory is broader than code quality scoring.

- **Not a project management framework.** Factory focuses on learning loops, not task tracking or sprint planning.

- **Not a training program.** It provides reusable artifacts, not curriculum (though talks may serve onboarding).

---

## The Core Loop

```
frame problem → slice ACT → patch small → verify hard → capture learning
```

1. **Frame problem** — Understand what needs to change and why it matters.
2. **Slice ACT** — Break work into small, actionable, concrete, time-bound increments.
3. **Patch small** — Make focused changes that can be verified independently.
4. **Verify hard** — Test against real evidence, not assumptions.
5. **Capture learning** — Extract patterns into doctrine, update templates, document examples.

Repeat.

---

## Key Relationships

| Artifact | Role | Example |
| -------- | ---- | ------- |
| **Concept** | Vocabulary definition | What is an ACT? |
| **Doctrine** | Evidence-backed policy | "Small patches verify faster" |
| **Playbook** | Step-by-step procedure | "How to run a Project Fitness Review" |
| **Template** | Copy/fill artifact | Review template, Epic template |
| **Example** | Teaching illustration | "Here's a review of project X" |
| **Gates** | Verification checkpoints | Score thresholds, checklist completions |

---

## Modules and Tools

Factory includes the **Project Fitness Review** as its first complete module—a framework for evaluating whether a software project can evolve safely. This module demonstrates the full loop from frame (what to evaluate) to capture (how to report findings).

Other modules are being developed:
- Doctrine extraction from repeated reviews
- Playbooks for common Factory workflows
- Templates for epics, ACTs, and close reports

---

## Scope and Constraints

Factory is deliberately modest. It does not:

- Expand to cover unrelated domains
- Add unfinished doctrine or untested patterns
- Reference private projects in public documentation
- Overclaim maturity or completeness

The process evolves through use, feedback, and evidence—not ambition.
